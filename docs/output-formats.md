# 출력 포맷 스펙

## 공통 원칙

- **쇼츠가 기준점**: 모든 포맷은 쇼츠의 핵심 메시지에서 출발
- **동일 주제, 다른 깊이**: 같은 날 같은 주제로 6개 포맷 생성
- **롱폼은 주간 종합**: 7일치 쇼츠를 관통하는 메타 분석
- **Notion 저장 → 점검 → 게시**: 모든 산출물은 Notion에 먼저 저장, 연구소장 점검 후 최종 게시

## 1. 쇼츠 (Shorts) — 25-Slide Bible 기반

### 용도
유튜브 쇼츠 — 영상 대본 (매일 발행)

### 스펙
| 항목 | 값 |
|------|-----|
| 글자수 | **GPT 재료(25-Slide Bible)**: 800자 이내 / **Claude 최종 대본**: 600자 이내 |
| 슬라이드 | 정확히 25줄 고정 (S00~S24) |
| 영상 길이 | 90초 (최대 3분) |
| 톤 | 독설적, 냉소적, 의사결정 중심, 권위 있는 화자 |
| 구조 | Impact Hook → Mission & Origin → Raw Misery → Cold Pivot → Outcome & Shadow → Insight Now |

### 25슬라이드 내러티브 아크
```
[S00] Impact Hook — 제품 질감 + 숫자 파괴력 + 기업명 (3초 타격)
[S01~S04] Mission & Origin — 세상의 결핍 + 초기 굴욕의 나노 묘사
[S05~S11] Raw Misery — 성장 이면 모순 + 자존심을 버린 비참한 오브제
[S12~S15] The Cold Pivot — 생존 위해 버린 것/택한 것 + 심리적 갈등
[S16~S22] Outcome & Shadow — 성공의 화려함 + 인간적 대가(배신/번아웃/관계 붕괴)
[S23~S24] Insight Now — 2026년 현재 상태 + To-do/Not-to-do + 시청자 질문
```

### 각 슬라이드 4겹 구조
1. **Cold Fact(차가운 사실)**: 숫자/날짜/인물/결정/결과
2. **Hot Psychology(뜨거운 심리)**: 창업자/팀의 공포·집착·수치·합리화
3. **Decision(의사결정)**: 무엇을 버리고, 무엇을 택했는지(Why-Logic)
4. **Evidence Object(증거 오브제)**: 그 장면을 "보이게" 만드는 사물/공간/소리

### 최종 대본 출력 형식 (Claude 집필 결과물)
```
1) (영문 훅) | 한국어 한 줄
2) 한국어 한 줄
...
25) 한국어 한 줄
```

### 작성 규칙
- "대단하다" 칭찬 금물 → "지독하다", "집요하다", "오만하다" 사용
- 숫자와 상황의 대비 극대화 (통장 잔고 0원 vs 기업가치 9조 원)
- 단순 기업 연혁 나열 금지
- 미화/훈계/감동 금지. "노력/열정/꿈" 같은 포장 단어 금지
- 창업자의 '운'이 아닌 **'선택'과 '고통'**에 집중
- 초반 3초 후킹 필수 (S00)
- "그들은 노력했다" 금지 → **"그들은 ○○를 포기했다 / ○○를 배신했다"**처럼 칼로 자른다

## 2. 블로그 (Blog)

### 용도
네이버 블로그 / 티스토리 — SEO 최적화 글

### 스펙
| 항목 | 값 |
|------|-----|
| 글자수 | 1,500-2,500자 |
| 톤 | Strategy — 읽고 바로 실행 가능한 비즈니스 무기 |
| 제목 형식 | `기업명 (English Name) \| [ENGLISH HOOK] \| 한국어 서사 제목` |
| 구조 | Decision Thesis → 체크리스트 5개 → 실행 전략 → Not To-do → 팩트 근거 |

### 구조 상세 (v6.3)
```
[Decision Thesis] 이 기업의 승부처를 한 문장으로 정의
[체크리스트 5개] 실패/성공에서 뽑은 Yes/No 진단형 질문
[실행 전략] Immediate Actions 3~7개
[Not To-do] "하면 망한다" 치명적 실책 3개
[팩트 근거] 핵심 수치/사건 5~10개 연결
[CTA] 관련 글 링크, 구독 유도
```

### 작성 규칙
- 제목에 핵심 키워드 필수 포함
- H2 소제목으로 스캔 가능한 구조
- 쇼츠에서 다루지 못한 배경/맥락을 보충
- 출처/수치를 본문에 자연스럽게 포함
- 이미지 삽입 위치 표시: `[이미지: 설명]`
- 체크리스트는 반드시 "질문형"으로 (Yes/No 진단 가능)

## 3. 브런치 (Brunch)

### 용도
브런치스토리 — 에세이/칼럼형 글

### 스펙
| 항목 | 값 |
|------|-----|
| 글자수 | 1,500-2,500자 |
| 톤 | Philosophy — 리더의 고독을 문학적으로 재구성 (감정 과잉 금지, 장면 과잉 허용) |
| 구조 | 불가능한 모순 → 결단의 순간 → 대가(증거) → 잔상(Aftertaste) |

### 구조 상세 (v6.3)
```
[불가능한 모순] 서두에 1개 박기 (성장 vs 신뢰 / 속도 vs 안전 / 이상 vs 생존)
[결단의 순간] 밤, 사무실, 메일, 전화, 침묵을 사물/소리/빛으로 묘사
[대가] 관계 파탄, 번아웃, 배신을 "증거"처럼 제시
[잔상] 결론은 훈계가 아니라 잔상(Aftertaste)으로 끝내기
```

### 작성 규칙
- 블로그와 달리 **개인 시점(1인칭)** 활용
- "나는 ~라고 생각한다", "~를 보면서 느낀 건" 등
- SEO보다 **읽는 맛**에 집중
- 데이터를 직접 나열하지 않고 이야기 속에 녹여내기
- 문단 사이 호흡 (한 문단 3-4문장)
- 훈계/교훈 금지 — 장면과 잔상으로만 끝낸다

## 4. 롱폼 (Long-form) — 주간 종합

### 용도
유튜브 롱폼 영상 대본 — Weekly Wrap-up (차주 월요일 발행)

### 스펙
| 항목 | 값 |
|------|-----|
| 글자수 | 5,000-8,000자 |
| 영상 길이 | 8분 내외 |
| 톤 | 분석적, 냉소적, 권위 있는 연구소 화자 |
| 주기 | 주 1회 — 차주 월요일 (7일치 쇼츠 기반) |
| 구조 | Intro → Body (교차 편집) → Conclusion |

### 구조 상세 (3단계)
```
[Intro] 7개 기업이 서로 달라 보이지만 사실은 [하나의 공통점]이 있음을 선언
  주제 예시: 오만, 결핍, 생존 본능 등
  훅 포함 — 시청자의 호기심을 잡는 도발적 선언

[Body] 요일별 사례를 교차 편집하여 주제를 증명
  - 월~일 7개 쇼츠의 기업을 공통 주제로 엮음
  - 같은 카테고리 내 차이점 비교 분석
  - 각 쇼츠를 참조할 때 날짜/기업명 명시

[Conclusion] 기업의 흥망성쇠를 통해 배우는 인간 경영의 본질적 교훈
  - 뼈를 때리는 최종 인사이트
  - 시청자를 향한 철학적 질문으로 마무리
```

### 작성 규칙
- 7일치 쇼츠 대본을 모두 입력으로 받음
- 단순 나열이 아닌 **관통하는 하나의 거대한 주제(Pattern)** 도출
- "대단하다" 금물 → "지독하다", "집요하다", "오만하다"
- 창업자의 '운'이 아닌 **'선택'과 '고통'**에 집중
- 차트/비교표 삽입 위치 표시: `[차트: 설명]`

## 5. 스팀잇 (Steemit)

### 용도
Steemit — 블록체인 기반 글로벌 블로그 플랫폼 (매일 발행)

### 스펙
| 항목 | 값 |
|------|-----|
| 글자수 | 1,000-2,000자 |
| 톤 | Insight — 데이터 기반 분석가의 날카로운 해설 (블로그보다 글로벌, 브런치보다 직설적) |
| 언어 | 한국어 본문 + 영문 요약(3줄) 하단 병기 |
| 구조 | Fatal Hook → Dirty Origin → Cold Pivot → Brutal Reality → Takeaway |
| 마크다운 | 네이티브 마크다운 (H2/H3, 인용문, 구분선, 볼드) |

### 구조 상세
```
[Fatal Hook] 쇼츠 S00 기반 — 상식을 파괴하는 한 줄 오프닝
[Dirty Origin] 창업자의 결핍과 굴욕 (블로그보다 압축적)
[Cold Pivot] 생존을 위한 잔혹한 선택 1가지에 집중
[Brutal Reality] 선택의 결과 — 숫자로 증명
[Takeaway] To-Do / Not To-Do + 독자를 향한 질문
[English Summary] 3줄 영문 요약 (글로벌 독자용)
```

### 작성 규칙
- 블로그의 체크리스트/실행전략을 **서사형으로 압축**
- 마크다운 인용문(`>`)으로 창업자 발언 강조
- 태그 5개: `#successfailure` `#startup` `#business` + 기업명 + 주제 키워드
- 영문 요약은 기계 번역이 아닌 **네이티브 톤** (글로벌 커뮤니티 타깃)
- 이미지 1-2개 삽입 (쇼츠 이미지 중 선별)
- 스팀잇 커뮤니티 특성: 투자/창업/테크 독자 → 수치와 의사결정에 무게

## 6. X (Twitter)

### 용도
X (구 트위터) — 쓰레드 형식 마이크로 콘텐츠 (매일 발행)

### 스펙
| 항목 | 값 |
|------|-----|
| 형식 | 쓰레드 5-7개 트윗 |
| 글자수 | 트윗당 280자 이내 (한글 기준 140자) |
| 톤 | Punch — 한 문장이 곧 무기. 짧고 강하게 |
| 언어 | 한국어 (해시태그만 영문 병기) |

### 쓰레드 구조
```
[1/N] Hook — 쇼츠 S00 기반, 스크롤을 멈추는 한 문장
[2/N] 결핍 — "이 회사가 시작된 이유는 ___였다"
[3/N] 수치 — 충격적 숫자 대비 (before vs after)
[4/N] 피봇 — "그가 내린 선택: ___를 버리고 ___를 택했다"
[5/N] 결과 — 현재 상태 한 줄
[6/N] 인사이트 — To-Do / Not To-Do
[7/N] CTA — "어떤 선택을 하겠습니까?" + 해시태그
```

### 작성 규칙
- **1트윗 = 1생각**. 접속사 완전 금지
- 첫 트윗(Hook)이 리트윗을 결정 → 가장 자극적인 숫자/반전 배치
- 마지막 트윗에 해시태그 3-5개: `#성공실패연구소` `#기업명` `#startup` 등
- 이미지: 첫 트윗에 1장 (쇼츠 S00 이미지)
- 이모지 최소 사용 (연구소 톤 유지). 구분용 `→` `|` 허용
- 숫자와 대비를 극대화: "0원 → 9조" 형태

## 7. 스레드 (Threads)

### 용도
Threads (Meta) — 대화형 마이크로 블로그 (매일 발행)

### 스펙
| 항목 | 값 |
|------|-----|
| 형식 | 단일 포스트 또는 연결 포스트 2-3개 |
| 글자수 | 포스트당 500자 이내 |
| 톤 | Conversational Edge — X보다 부드럽되, 날카로운 관점은 유지 |
| 언어 | 한국어 |

### 구조
```
[메인 포스트] Hook + 핵심 서사 압축 (500자)
  - 쇼츠의 핵심 메시지를 대화체로 풀어씀
  - "~했거든요" "~인 거죠" 등 구어체 허용
  - 마지막에 질문으로 댓글 유도

[연결 포스트 1] (선택) 보충 데이터 또는 인용구
[연결 포스트 2] (선택) CTA — 유튜브/블로그 링크
```

### 작성 규칙
- X 쓰레드를 **하나의 덩어리로 압축**하는 느낌
- 인스타그램 사용자 기반 → **비주얼 감각** 중요, 이미지 1장 필수
- 대화체 허용하되 **가벼운 유튜버 말투 금지** (연구소 정체성 유지)
- 해시태그: 본문 하단에 5-8개 (한글+영문 혼합)
- "~입니다" 체 금지 → "~였다" 또는 "~거든요" 체 허용
- 댓글 유도 질문 필수: "여러분이라면?" 형태

## 포맷 간 관계도

```
                    ┌──→ 블로그 (정보 확장, SEO)
                    │
                    ├──→ 브런치 (에세이 전환)
[매일]  쇼츠 ──────┤
                    ├──→ 스팀잇 (글로벌 분석)
                    │
                    ├──→ X 쓰레드 (마이크로 펀치)
                    │
                    └──→ 스레드 (대화형 압축)

[주간]  쇼츠 7개 ──→ 롱폼 (종합 분석)
```
