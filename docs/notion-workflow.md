# Notion 저장 & 게시 워크플로우

## 개요

모든 콘텐츠 산출물은 **Notion에 먼저 저장**되고, 연구소장이 **점검 후 최종 게시 명령**을 내리는 구조이다.
이 프로세스는 오류를 방지하고, 전체 포맷 간 일관성을 보장한다.

---

## 1. Notion 폴더 구조

### 주간 데이터베이스 구조

```
📁 성공실패연구소 콘텐츠
├── 📁 2026-W08 (주간 폴더)
│   ├── 📁 2026-02-16_월_기업명A
│   │   ├── 📄 쇼츠 (대본 + 이미지 프롬프트)
│   │   ├── 📄 블로그 (네이버)
│   │   ├── 📄 브런치
│   │   ├── 📄 스팀잇
│   │   ├── 📄 X (쓰레드)
│   │   ├── 📄 스레드 (Threads)
│   │   └── 🖼️ 이미지 (GenSpark 산출물)
│   │
│   ├── 📁 2026-02-17_화_기업명B
│   │   ├── 📄 쇼츠
│   │   ├── 📄 블로그
│   │   ├── 📄 브런치
│   │   ├── 📄 스팀잇
│   │   ├── 📄 X
│   │   ├── 📄 스레드
│   │   └── 🖼️ 이미지
│   │
│   ├── ... (수~일, 7일치)
│   │
│   └── 📁 2026-02-23_롱폼_주간종합
│       ├── 📄 롱폼 대본
│       └── 📄 롱폼 이미지/차트
```

### 폴더 네이밍 규칙

| 항목 | 형식 | 예시 |
|------|------|------|
| 주간 폴더 | `YYYY-Www` | `2026-W08` |
| 일일 폴더 | `YYYY-MM-DD_요일_기업명` | `2026-02-16_월_토스` |
| 롱폼 폴더 | `YYYY-MM-DD_롱폼_주간종합` | `2026-02-23_롱폼_주간종합` |

## 3. 상태 관리 (Status Workflow)

```
[초안]  →  [점검중]  →  [수정요청]  →  [승인]  →  [게시완료]
  ↑                        │                        │
  │                        └── 수정 후 재제출 ──────┘
  │
  Claude가 생성 후 자동 저장
```

### 상태 정의

| 상태 | 의미 | 다음 액션 |
|------|------|----------|
| **초안** | Claude가 생성하여 Notion에 저장 완료 | 연구소장 점검 시작 |
| **점검중** | 연구소장이 검토 중 | 수정요청 또는 승인 |
| **수정요청** | 연구소장이 피드백 남김 | Claude가 수정 후 재저장 |
| **승인** | 연구소장이 게시 승인 | 게시 대기 |
| **게시완료** | 각 플랫폼에 게시 완료 | 게시 URL 기록 |

## 4. 점검 체크리스트 (연구소장용)

### 일일 점검 (6개 포맷)

- [ ] **쇼츠**: S00 훅 파괴력 / 피봇 위치 / 600자 이내 / 팩트 정확성
- [ ] **블로그**: 제목 SEO / 체크리스트 5개 / 이미지 슬롯 / 해시태그 20개
- [ ] **브런치**: 톤 서늘함 / 문단 리듬 / 잔상 마무리 / 이미지 1:1
- [ ] **스팀잇**: 영문 요약 품질 / 태그 적절성 / 마크다운 정합성
- [ ] **X**: 첫 트윗 후킹력 / 트윗 독립성 / 140자 준수 / 해시태그
- [ ] **스레드**: 대화체 톤 / 500자 이내 / 댓글 유도 질문 / 이미지

### 포맷 간 일관성

- [ ] 6개 포맷의 **핵심 메시지가 동일**한가?
- [ ] 팩트/수치가 포맷 간 **모순 없이 일치**하는가?
- [ ] 각 포맷이 **플랫폼 특성에 맞게 변환**되었는가?

## 5. 게시 프로세스

### 연구소장 최종 게시 명령 후

| 순서 | 플랫폼 | 시간 (KST) | 비고 |
|------|--------|-----------|------|
| 1 | YouTube (쇼츠) | 07:30 | 출근 시간대 타깃 |
| 2 | 네이버 블로그 | 08:00 | SEO 인덱싱 시간 확보 |
| 3 | 브런치 | 08:30 | 출근길 독서층 |
| 4 | Steemit | 09:00 | 글로벌 시간대 고려 |
| 5 | X | 12:00 | 점심시간 SNS 피크 |
| 6 | Threads | 18:00 | 퇴근 후 인스타 사용 피크 |

### 게시 후 기록

각 포맷의 Notion 페이지 하단에 게시 URL과 시간을 기록:

```
━━━ 게시 기록 ━━━
게시일시: 2026-02-18 07:30 KST
게시 URL: https://youtube.com/shorts/xxxxx
성과 메모: (조회수, 댓글 반응 등 — 추후 기록)
```

## 6. 주간 롱폼 프로세스

1. 일~토 6일간의 **승인된** 쇼츠 대본을 수집
2. Claude에게 7일치(일~토) 쇼츠 입력 → 롱폼 대본 생성
3. Notion `롱폼_주간종합` 폴더에 저장
4. 연구소장 점검 → 승인
5. 차주 월요일 게시

## 7. 이미지 관리

### 이미지 저장 위치
- 각 일일 폴더의 `이미지` 하위 섹션에 GenSpark 산출물 저장
- 파일명 규칙: `S00_hook.png`, `S01_origin.png`, ... `S24_question.png`

### 이미지 활용 매핑

| 포맷 | 사용 이미지 |
|------|-----------|
| 쇼츠 | S00-S24 전체 25장 |
| 블로그 | S00, S04, S08, S12, S16, S20, S23, S24 (~8장, 16:9 별도) |
| 브런치 | S00, S12, S16, S24 (3-4장, 1:1 별도) |
| 스팀잇 | S00, S12 (1-2장) |
| X | S00 (1장) |
| 스레드 | S00 또는 S12 (1장) |
